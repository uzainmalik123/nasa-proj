HOW TO USE
----------
1. Open a Claude Code session in the NEW repo directory.
2. Paste ONE prompt block from below (everything between the ---- lines).
3. Each prompt is self-contained: it tells the session what to read, what it
   owns, what "done" means, and how to hand back.
4. The PARALLEL MAP says what may run at the same time. Never run two prompts
   that own the same directory at once.
5. You review by outcome only: the proof the session hands back (screenshot
   path, JSON sample, gate output). Do not read diffs.

Paths: draft folder with the docs is  ~/Projects/hackathons/NASA/draft
       new repo is wherever you create it (call it  ~/Projects/hackathons/NASA/etd )

Bootstrap the hackathon repo for "Earth System Trend Detective".

1. Create a git repo in the current directory, default branch main, and a
   .gitignore for Python (uv .venv, data/), Node (node_modules, .next,
   next-env.d.ts), .env*, and dashboard/public/data/*.json except mock files.
2. Copy ~/Projects/hackathons/NASA/draft/docs/{PRD.md,DESIGN.md,contracts.md,prep.md}
   into docs/. Read all four. contracts.md defines the repo layout; create it exactly.
3. pipeline/: `uv init --python 3.12`, then `uv add numpy pandas pyarrow
   scikit-learn scipy shap xgboost-cpu requests pymannkendall python-dotenv
   ruff`. Use xgboost-cpu, never xgboost. Create config.py with every
   constant named in contracts.md §4, PLACE_TIER=1, and FIRMS_LIVE_SOURCE
   set to the value in pipeline/.env if present else "VIIRS_NOAA21_NRT".
   Create run.py that imports the stage modules in order (ingest → places →
   trend → features → hazards → publish → gates) with each stage a stub that
   logs its name, so the skeleton runs end to end in under 5 s.
4. dashboard/: `npx create-next-app@latest dashboard --ts --tailwind --app
   --src-dir --eslint --no-import-alias` then `npm i maplibre-gl d3-scale
   d3-shape d3-interpolate` and their @types. Add the copy-worker script and
   postinstall/predev/prebuild hooks described in prep.md §9 (MapLibre
   worker served from public/). Put the tokens from DESIGN.md §2 into
   src/app/globals.css and src/lib/palette.ts verbatim. Create src/lib/types.ts
   mirroring contracts.md §3 exactly, and src/lib/data.ts with loadAll().
5. pipeline/places/build_places.py: download Natural Earth
   ne_10m_populated_places (zip, public domain), select national capitals
   plus pop_max ≥ 1,000,000, dedupe within 50 km keeping the larger, assign
   place_id per contracts §2 and continent from the ADM0 country via a small
   lookup. Write data/places.parquet and dashboard/public/data/places.json.
   Print the count; it should be roughly 500–700.
6. Mock data: write pipeline/publish/mock.py that generates every file in
   contracts §3 for the FIRST 20 places with plausible random values, into

7. .github/workflows/pipeline.yml: cron "0 */3 * * *" + workflow_dispatch;
   checkout; uv sync; run pipeline/run.py with secrets FIRMS_MAP_KEY,

8. Read pipeline/.env (I will have placed it) and run the FIRMS source test:
   fetch world/1 for VIIRS_NOAA21_NRT, VIIRS_NOAA20_NRT, VIIRS_SNPP_NRT,
   MODIS_NRT, print row counts, and set FIRMS_LIVE_SOURCE in config.py to the
   VIIRS source with the most rows. Print the choice.
9. Commit everything on main. Create branches s1-ingest, s2-science,
   s3-globe, s4-panels from main.
10. Handback: the place count, the FIRMS source chosen, `npm run build`
    output tail, `uv run python pipeline/run.py` output, and a screenshot of
    the Next.js default page at localhost:3000 proving the dev server works.

----  S1-A  INGEST + COLD RUN   (branch s1-ingest; owns pipeline/ingest, .github)
[standard preamble applies]
Implement PRD §7.2 steps 1–3 as pipeline/ingest/{firms,power,openmeteo}.py
writing the parquet caches defined in contracts.md §4.
- power.py: per place, fetch from the last cached date to today (first run:
  2016-01-01), parameters T2M,T2M_MAX,PRECTOTCORR,RH2M,WS2M,GWETROOT,GWETTOP,
  community=AG. Pace at POWER_PACE_S between requests, retry 3× with backoff
  on 429/5xx. Replace -999 with null. One parquet per place.
- firms.py: (a) live: world/1 for FIRMS_LIVE_SOURCE and for MODIS_NRT;
  (b) history: MODIS_SP in 5-day chunks (world is capped at 5 days) back 12
  months, skipping chunks already cached; filter type==0 (vegetation fire)
  for counts; KD-tree join (scipy cKDTree on unit vectors) to places within
  RADIUS_KM; write firms/{date}.parquet and firms_counts.parquet.
- openmeteo.py: 16-day daily forecast per place, variables in PRD §6, one
  request per place, write forecast/{run_id}.parquet.
- Wire all three into run.py's ingest stage and write freshness.json per
  contracts §3 (valid_for = newest data timestamp, retrieved_at = now).
Then push the branch and trigger the workflow with workflow_dispatch so the
COLD RUN starts in GitHub Actions. Watch it. The cold run must start before
11:00. If POWER throttles, lower the place count via PLACE_TIER logic and say so.
Handback: Actions run URL, its duration, row counts per cache, freshness.json.

----  S2-A  TREND ENGINE + FEATURES   (branch s2-science; owns pipeline/trend, pipeline/features, pipeline/publish)
[standard preamble applies]
Implement PRD §7.2 step 4 (trend engine) and step 5 (features).
- trend/mk.py: for each place and each variable in contracts §3 trends.json,
  Mann-Kendall (pymannkendall.original_test) with Sen's slope on (a) 120
  monthly means over 10 years and (b) the last 90 daily values. Labels per
  contracts. Vectorise by place with a simple loop; 600×6×2 tests must finish
  under 2 min. Write trends.json via publish/write_json.py.
- features/build.py: one row per place per day for the last 13 months:
  7/30/90-day rain sums and anomaly z vs the place's own climatology for that
  calendar window (computed from the 10-year cache, smoothed ±15 days), tmax
  and rh anomalies, soil wetness and 30-day change, fire weather index (a
  simple Angstrom-style index from tmax, rh, wind, days since rain) over the
  observed window and over the next 14 days (observed future in training
  rows, forecast at inference), fires last 7/30 days, days since last
  detection, trend slopes, lat, lon, doy sin/cos. Label = ≥ LABEL_MIN_DETECTIONS
  MODIS detections within the next HORIZON_DAYS; label_valid False where the
  future is not observed; split = "holdout" for the final 6 weeks.
Until S1-A's caches exist, develop against a synthetic parquet you generate
with the same schema (keep the generator in pipeline/dev/). Switch to real
caches the moment they appear on the data branch.
Handback: trends.json sample for 3 places, features.parquet shape and column
list, label rate, runtime of each stage.
